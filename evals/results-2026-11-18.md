# Eval results — beezwax-bbox-plugin 1.2.0 — 2026-11-18

This release changed catalog data (SQLite family flagged deprecated) and SKILL.md guidance, so
all four cases were re-run on Haiku (the model most likely to miss guidance), each run in a
fresh subagent with the skill folder only (no `evals/`, no web). The new case was also run
against the released 1.1.1 as the baseline.

| Case | 1.2.0 (Haiku) | 1.1.1 baseline (Haiku) | Notes |
|---|---|---|---|
| function-lookup-error-pattern | ✅ | — | bBox_LastError(-3), mode +32, catalog example quoted |
| stub-vs-full-hedging | ✅ | — | Flagged `full_demo_confirmed`: no wiki page, no examples or version history |
| container-field-and-thread-safety | ✅ | — | Temp `.bin` file and purge, shared Python VM, PSoS and stored-calc limits |
| deprecated-sqlite | ✅ | ⚠️ 2/3 | See below |

Score: 1.2.0 4/4.

`deprecated-sqlite`: both versions steered new work to `bBox_DuckDBOpen`/`Exec`/`Close` and
said existing scripts still run. Only 1.2.0 reported the vendor's deprecation (Beezwax removed
the family from the wiki function index) and used the `replaced_by` pointers; 1.1.1 called the
functions "superseded" based on older pages' notes. The case is a weak discriminator, since the
old catalog already preferred DuckDB, but it confirms the new flag is read and reported.
